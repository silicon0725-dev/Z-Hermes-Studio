# ADR-0003：长对话性能 —— 基准方法与验收口径

- 状态：**Accepted**（目标数字冻结自开发文档 §7.4；基准框架已建并产出首轮数据，见 docs/PERFORMANCE.md；差距与优化计划在案）
- 日期：2026-10-17（初版）；2026-10-17 基准框架落地
- 依据：开发文档 v0.1 §7、§15.3；M0 盘点 §2.4、§2.5

## 背景

开发文档把长会话性能定为 P0，并给出初始目标数字，但"可交互"等指标缺少操作化定义，50k 规模未定义口径，基准如何驱动 Avalonia UI 未指定。本 ADR 补齐这三件事，使 §7.4 的数字可重复验证。

## 决策

### 1. 指标操作化定义

| 指标 | 定义（判定方式均为程序化计时，非人工感知） |
|---|---|
| 首屏可交互 | 主窗口首次渲染完成 **且** 首页消息（默认 60 条）完成数据绑定与布局 **且** 输入控件可用，三者取最晚时刻 − 会话打开起始时刻 |
| 滚动帧时间 | 虚拟化列表滚动期间逐帧采样；P95 ≤ 16.7 ms |
| UI 主线程单次同步工作 | Dispatcher 上单次连续执行时长；目标 ≤ 8 ms |
| 流式更新频率 | 生成期间 UI 实际提交批次/秒（预算 30–60 Hz，按设备分级） |
| 50k 规模 | **单会话** 50,000 条消息（另含 1k、10k 两档） |

### 2. 数据集

- 固定 seed 的生成器产出，混合比例固定：纯文本 / Markdown（标题、列表、表格）/ 代码块 / 工具调用与结果（含超长输出）/ 附件引用 / 错误与中断事件。
- 数据集内容 hash 随结果一并记录；数据生成器入库（`benchmarks/`）。

### 3. 基准框架

- **Avalonia.Headless + 帧调度计时**驱动 UI，不以真机人工计时替代；另在参考机型上跑端到端采样核对量级。
- 每轮记录：P50/P95/P99、内存峰值、Gen0/1/2 GC 次数与暂停合计、事件队列深度、合并/丢弃计数、数据库读取与解析分项耗时。
- 环境记录：硬件、OS、commit、构建模式（Release）、.NET/Avalonia 版本、数据集 hash。**原始样本全量落盘，禁止只保留平均值。**

### 4. 流式数据路径规则（冻结）

- Runtime → 协议解码 → **有界 Channel**（容量与丢弃/合并策略显式配置）→ 合并器 → UI 调度 → 仅更新活动消息。
- 结构化事件（工具、审批、终止）不参与合并；每次增量校验 `messageId + sequence`（上游 part 自带 sequence，见 M0 §2.5，直接透传）。

## 备选方案与否决理由

| 备选 | 否决理由 |
|---|---|
| 仅靠生产环境埋点 | 不可重复，无法防回归 |
| 真机人工计时 | 主观且不可回归 |

## 后果

- M2 验收 = 本 ADR 定义的口径下达到 §7.4 数字，或记录可复现差距与优化计划。
- 首页条数（60）为初始值，基准数据可调整并在本 ADR 更新。

## 开放问题

- 参考机型分级（低/中/高端）与判定阈值待定；无头基准与真机采样的偏差范围需首轮数据校准。
